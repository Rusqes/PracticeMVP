Техническое задание
Sprint Tracker MVP
Веб-приложение для ведения global backlog и планирования спринтов
1. Цель проекта
Необходимо разработать веб-приложение для ведения global backlog и планирования спринтов компании.
Сейчас трекер ведется вручную в Google Sheets. Основная логика работы:
хранение эпиков;
хранение задач внутри эпиков;
управление справочниками;
планирование задач по спринтам;
отображение прогресса по эпикам;
drag-and-drop;
сортировка задач;
работа с результатами выполнения.
Проект должен быть реализован как MVP.

3. Основные сущности системы
3.1. Product / Продукт
Продукт — направление или проект компании.
Примеры: Проект 1, Проект 2, Сайт, Калькулятор, Иной проект
можно создавать продукт;
можно редактировать название;
продукт выбирается у эпика и задачи;
список продуктов должен быть управляемым через интерфейс.
3.2. Stream / Стрим
Стрим — тип направления работы.
Примеры: Продуктовый, Инженерный, Смешанный
можно создавать стрим;
можно редактировать название;
стрим выбирается у эпика и задачи;
список стримов должен быть управляемым через интерфейс.
3.3. Status / Статус
Статус отражает состояние эпика или задачи.
Примеры: Новая, Запланировано, В реализации, Выполнено, Отклонено, Заморожено
можно создавать статус;
можно редактировать название;
можно задавать цвет статуса;
Статус «Выполнено» должен использоваться при расчете прогресса эпика.
3.4. Task Type / Тип задачи
Тип задачи описывает характер работы.
Примеры: Новый функционал, Улучшение, Инфраструктура, Исследование
можно создавать тип задачи;
можно редактировать название;
можно задавать цвет;
тип задачи выбирается у задачи.
3.5. Performer / Исполнитель
Исполнитель — человек, который участвует в выполнении задачи.
Примеры:Вася, Петя, Саша 
можно создавать исполнителя;
можно редактировать имя;
можно делать исполнителя неактивным;
у одной задачи может быть несколько исполнителей;
у задачи может быть выбран один ответственный исполнитель (ответственного может и не быть);
ответственный должен быть одним из выбранных исполнителей.
Пример:Исполнители: Вася, Петя, СашаОтветственный: Саша

4.2. Прогресс эпика
У каждого эпика должен отображаться прогресс по задачам.
Формат: 4 из 6
6 — общее количество задач в эпике;
4 — количество задач со статусом, который считается выполненным.
Если у эпика нет задач, можно показывать «0 из 0» или «—».

5. Сортировка задач
В backlog и в спринтах задачи должны сортироваться по дате.
1.  Сначала задачи без статуса «Выполнено».
2.  Внутри них — по плановой дате.
3.  Выполненные задачи уезжают в конец списка.
4.  Внутри выполненных задач — сортировка по фактической дате или плановой дате.
Пример порядка:09.07.2026 — Запланировано10.07.2026 — В реализации11.07.2026 — Заморожено08.07.2026 — Выполнено
Задача со статусом «Выполнено» должна быть ниже активных задач, даже если ее дата раньше.
6. Drag-and-drop
В системе должен быть drag-and-drop.
6.1. В backlog
можно менять порядок эпиков;
можно менять порядок задач внутри эпика.
6.2. В спринтах
можно менять порядок задач внутри спринта;
желательно можно перетаскивать задачи между спринтами, если это не слишком усложняет реализацию.
После перетаскивания порядок должен сохраняться в базе данных. Для этого можно использовать поле sort_order.

8. Добавление задачи в спринт
При добавлении задачи в спринт пользователь должен выбрать:
1.  Эпик из global backlog.
2.  Задачу из выбранного эпика.
3.  Плановую дату выполнения задачи в рамках спринта.
После выбора задачи остальные поля должны подтянуться автоматически из самой задачи:
название;
эпик;
статус;
исполнители;
ответственный;
тип задачи;
продукт;
стрим;
результат;
Пользователь вручную заполняет или меняет:
плановую дату;
фактическую дату;
отклонение;
комментарий.
9. MVP-экраны
9.1. Экран Global Backlog
список эпиков;
задачи внутри каждого эпика;
прогресс эпика;
возможность создать эпик;
возможность создать задачу внутри эпика;
возможность редактировать эпик;
возможность редактировать задачу;
drag-and-drop для изменения порядка.
9.2. Экран Sprint Planning
список спринтов;
даты каждого спринта;
визуальное выделение месяцев;
список задач внутри спринта;
кнопка добавления задачи в спринт;
выбор эпика;
после выбора эпика — выбор задачи;
ручной выбор плановой даты;
ручной ввод фактической даты;
отображение подтянутых полей задачи.
9.3. Экран Settings / Справочники
На экране должны быть вкладки или блоки: продукты, стримы, статусы, типы задач, исполнители.
Для каждого справочника должны быть доступны создание, редактирование, удаление
